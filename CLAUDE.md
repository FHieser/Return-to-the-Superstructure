# Return to the Superstructure — project context

Fan project: pen & paper one-shots set in the world of the game **White Knuckle**. Built and maintained together with Claude. This file carries the context of the original working sessions; read it before changing anything.

Sibling project with the same approach: `../Horror-One-Shots` (static site, YAML data + webapp per adventure, GitHub Pages deploy).

## How the site works

- **Static site, no build step.** Pages are plain HTML; YAML is fetched in the browser and parsed with js-yaml, Markdown with marked (both from cdnjs). Deployed to GitHub Pages by `.github/workflows/deploy.yml` (Pages source must be "GitHub Actions").
- Data files are fetched with `cache: 'no-cache'` (core.js `fetchText`), so edited YAML shows on a normal reload; CSS/JS changes may still need Ctrl+F5.
- **Run locally:** `python -m http.server 8000` in the repo root, open `http://localhost:8000/`. Pages need a server (they fetch YAML).
- **Every folder pairs `data/` (human-readable YAML, the source of truth) with `webapp/` (display only).**

```
index.html                 landing page: lore card first, then one-shot cards
favicon.svg                the user's own "Superstructure Favicon" (4 slanted light strips); has a viewBox, keep it
shared/css/style.css       all styles; shared/css/dither.png = grey dithered background tile
shared/js/core.js          data loading, header, lore loader, fan project intro, fan-made mode, radiation effect
shared/tools/make-dither.js regenerates dither.png
lore/data/                 THE LORE (source of truth) — see below
lore/webapp/               index (cavity map), substructure.html?id=, peripheries.html (orbit), periphery.html?id=,
                           codex.html?c=entities|objects, timeline.html (heart monitor); js/lore.js
one-shots/catalog.yaml     which one-shot folders the landing page lists
one-shots/_template/       copy to start a one-shot (data/ + webapp/ + js/app.js)

shared/js/mural.js         the one-shot Rooms page: a wall painted black with words whose letters shift (data/rooms.yaml)
one-shots/the-dark-side-of-the-room/   first one-shot (in progress)
```

## Lore data model (`lore/data/`)

- `overview.yaml` — lore title etc.
- `map.yaml` — cavity map: substructure positions on a diamond grid ([column,row], SB01 at [3,3]), walls, tram_lines, roads, `landmarks` (e.g. North Entry). Layout from "Superstructure Cavity Map by Chipper (fan map)". **It is also the index of `substructures/`** (static hosting can't list folders).
- `substructures/` — one file per substructure (`sb01`…`sb21`, `unknown`), plus `_superstructure.yaml` (the Superstructure as a whole, shown on the map page).
- `orbit.yaml` — index + order of `peripheries/`. Files are numbered by Greek alphabet (`01-alpha` … `24-omega`); the number only sorts, the id is the name (`delta`). `00-baseline.yaml` = Baseline Reality (`stable: true` → fixed square in the orbit centre). `_peripheries.yaml` = peripheries in general.
- `entities.yaml`, `objects.yaml` — codex collections (still empty).
- `timeline.yaml` — eras → events (date, title, text, related, sources, canon, one_shots).
- (Places, People and Factions were deliberately dropped.)

Common fields: `summary` (one line, used in hover cards), `sections` (full text: heading + Markdown body — **the user wants full prose with proper sections, never bullet points**), `related`, `sources`, `open`, `canon` (confirmed | developer | theory | ours).

Display rules:
- Substructures/peripheries with no summary/sections/related/sources show as **"No known information"** (dim/dashed), unless `marked: true` (ring on map, bright). Never write "Nothing written yet".
- Marked substructures: SB03 (Blue/Lambda), SB07 (Red/Rho), SB17 (Yellow/Delta). Colours/habitations/peripheries on the map come from the user's map image (SB20/SB21 left out).
- Peripheries have `show` (only Baseline, Delta, Zeta, Kappa, Lambda, Rho, Mu are shown), `symbol` (Δ, ζ, Κ, λ, ρ, μ — Delta stays capital Δ), `color` (empty = colour of the researching substructure).

## Fan-made content ("fan-made mode")

- The lore is collected from the White Knuckle community wiki (whiteknuckle.miraheze.org). It may be wrong/outdated; we adapt it where stories need it.
- **Fan-made mode** = button bottom-right on every page (four light strips; off = dark, on = steady white light, white box, constant white radiation pixels hugging the button with a gaussian falloff). Switching re-renders the page in place (no reload); the orbit keeps running and fades peripheries in/out. Stored in localStorage `rtts-fan-mode`.
- In fan mode only: entries with `canon: ours` (e.g. Periphery Mu), timeline events with `canon: ours` (drawn **red** on the heart monitor, incl. pulse and era marker), map `landmarks` with `canon: ours`, and `fan:` blocks inside any lore file (their `sections` are appended in red with a Fan-made badge, other fields replace — e.g. SB14 gets `periphery: mu`).
- Fan project note: footer "Read more" + first-visit intro overlay (text in `FAN_TEXT` in core.js, single-pixel white "radiation" swarming the panel). Discord link still missing (no invite link yet). GitHub link: github.com/FHieser.

## Working preferences (from the user)

- Ask before inventing lore or story content; build one-shots **together**. Only write what the user gave; mark gaps "To be defined".
- When the user pastes wiki text: keep wording close, split into summary + sections, drop footnote markers like [1], fix small grammar, report what was changed.
- Visual style: dark, grey dithered background, white "SB17 INDUSTRIAL" plate look; horror details welcome but **not aggressive**. White, not red, for the fan-mode button and its particles.
- Keep things in data files, not hard-coded. Each data file starts with a comment explaining its fields.
- **Maps:** the user sketches in draw.io (`.drawio` files in the one-shot's `data/`, e.g. `Road to Maroon.drawio`), and Claude **reproduces** each sketch by hand in `data/map.yaml` (sections with walls, elevated roads, areas, markers; links via `location`/`lore`, GM `note`s). The site does not read the .drawio files (the user decided against it). The road map uses the lore cavity grid ×8 with the North Entry at [0,0] (SB14 at [8,8]). Keep the user's .drawio files. GM tokens are saved per map in localStorage `rtts-map-<folder>`. The storage map (section `storage`) is reproduced from `Storage Maroon.drawio`: hall centre [0,0], 50 drawing-px = 1 unit; the diamond hall with the roundway (walkway up top) on all four walls, three entrances (north entry from the ice road, partly blocked but walkable; exits to SB06 and SB13), the Κ-Coolant field in the bottom corner (cracked foundations), standing / knocked-over shelves and debris (converted from the drawing's coordinates), the crane control room in the middle, the storage office and stairs on the upper-right wall, two destroyed staircases. Its zoomed-out sketch shows the hall as the diamond inside SB14 at road level (drawn on the road map as SB14's inner diamond). Also on it: the ceiling crane on a double-axis rail (reaches the whole hall), transport containers drawn by the user (the 50×20 rectangles, once mistaken for debris): 4 by the crane control room near the centre (the way up with the crane) and 3 by the north-east destroyed stairs near the office (best drop-down point), Barnacles in several ceiling spots as red zones (zone kind `barnacle`; only the centre, the likely crane hit, placed so far), Mu darkness in the gaps between wreckage and shelves and inside the crane control room building. Mu positions are approximate. The stairs by the office lead up into the labs.
- Test changes in headless Chrome against a local server; mark `rtts-fan-project-seen` in localStorage first, otherwise the intro's radiation keeps the headless browser busy. Only stop test servers you started yourself — never the user's server on port 8000. On this machine netstat says `ABHÖREN` (German), not `LISTENING`, and Python runs as `python3.13.exe`: find the test server's PID accordingly and kill only that PID.

## Lore written so far (highlights)

- Superstructure (RMSS, ITAA, discovered 1987), Peripheries in general, Baseline Reality, Delta, Lambda, Rho, Zeta, Kappa (Κ-Coolant), SB07 (Habitation Red, Rho cult, Dahl, the final act), SB12 (Habitation Green, climate core, Κ-Coolant suicides).
- Timeline: 1987 → 2034 from the wiki; fan-made Sep 2, 2034: Κ-Coolant floods the cavity floor (Dahl's sabotage opens coolant production to Kappa; the flow stops later, PCR failure or blocked inlet; higher roads stay usable but dangerous). The 266 days in the Aug 2034 entries are for the Rho plan, not the freeze. Fan-made 2042: Oct 10 the government's off-the-record expedition opens the north passage (weekly door protocol with cryptographic codes); late Oct 2042 the Mu expedition force sets out (linked to the one-shot).
- **Periphery Mu (fan-made, `12-mu.yaml`)**: Mu light is incompatible with baseline light — whatever it hits becomes invisible to baseline observers and the lit area turns pitch black (ordinary light doesn't help). Light still reaches objects (they warm up); only perception breaks, so sight-based tools fail; other senses and non-optical instruments work. Reverse direction never tested. Crossing over had only minor successes; entry points were mapped by touch and radiation detectors.
- Map landmark (fan-made): **North Entry** at [3,-1], on the wall between SB15 Magenta and SB14 Maroon — the expedition base.

## One-shot in progress: "The dark side of the room"

Folder `one-shots/the-dark-side-of-the-room/`. System: **HeartCore** (the user's Daggerheart modification). 3-5 players, 4-5 hours, tag: horror. Tagline: "The darkness is closing in." Premise: the intro to the whole White Knuckle lore — after decades of being closed off, the Superstructure opens up one more time; you travel to Substructure 14 and dive into the darkness. The expedition is the **Structure Reclamation Expedition (SRE)** (echoes the SRA).
- NPC: **expedition captain Holly** (gives the briefing, does not come along).

- Players are members of the 2042 expedition; base = North Entry. First one-shot: low pressure, builds basic understanding. Players start knowing very little; they learn what PCRs are and that peripheries exist, but what peripheries really are stays hidden or heavily restricted.
- Goals: gather information on Maroon's contents; look for survivors; see whether the PCR is online and functional; get research data. (The "do the trams work" goal was dropped.)
- Places in Maroon (`data/locations.yaml`): ice road → loading dock (safe area after the road, at the bottom) → storage (huge, plundered, cleared) → lab area → security door (opened with the dead scientist's security card) → PCR (check if running via a test run, get data).
- Act II's harmless enemy: Lambda denizens, probably Barnacles (entity `barnacle` in `lore/data/entities.yaml`, from the wiki). Info: scavenged records say Maroon researched Periphery Mu.
- Main challenge: Mu light sources in Maroon create pitch-black zones (navigate by sound, touch, smell, instruments). **Something hides in the dark — to be defined.**
- Session flow (`data/timeline.yaml`): Act I — camp at the North Entry, briefing, the road just above a sea of **liquid** Κ-Coolant (everything on the road is frozen), the view of the cavity's scale, the cold, dead convoy crew (proper clothing, not enough), the scrap convoy frozen to the road, still-usable items on the cars (pills, snack bars, flare gun; syringes broken by the frost, a nod to a game item). The ledge artifact was dropped. The view: the empty cavity, the substructure towers, the tram lines, the Κ-Coolant sea.
- **Periphery detector** (fan-made object `periphery-detector` in `lore/data/objects.yaml`), handed out at the briefing: a Geiger counter for shifts in reality around a living ear in glass with the Rho symbol (inspired by the Blink Eye — the wiki says the Blink Eye is Baseline, not Rho). Hears peripheries but not Rho (Rho doesn't want to be listened in on). A Rho-infused item (origin: rho). 3 charges, no regeneration; when empty the glass is red with blood. Beeps like a radiation counter in Mu light. At the table: switch it on → ask the GM whether something is periphery-based and how far the next anomaly is → one charge used. Act II — "fuck around", the players go through all of Maroon: loading dock (safe), storage (oddly harsh shadows in spots where lights don't work — first harmless Mu contact, no barrier), a Barnacle in the storage (players hear its tendrils; later Barnacles sit in Mu light in the dark and are recognized by that sound), the storage's loading cranes (stairs broken; remote control only from a panel — at the bottom or on top near the labs, undecided — so someone stays behind unless someone sets up an auto-loop through fixed positions), the labs (lobby, then a harmless black wall in the hallway, bypassed through the office), the security door (security card), reaching the PCR, the test run. Act III — "Blackout" ("find out") starts with the power surge caused by the test run: a round wall of blackness expands from the PCR as the area floods with Mu light → total darkness; they traverse the way in backwards, out of Maroon, by sound cues and distinctive textures/places (GM tracks positions privately on the PC); at places with normal light, flickering Mu light gives moments of sight; the loading cranes are the last "boss" on the way out: someone stays back at the panel, or the players drop and jump down, risking injury or death. Once out of Maroon, the surge and the one-shot end. The **Mu flashlight** (fan-made object `mu-flashlight`) can be found in the PCR room at the end of Act II: it casts a beam of Mu light (shone into eyes, it turns the view black) and blinds the monster; just a gimmick here, in later one-shots it can blind enemies. Wanted, not a conflict: the beam opens a path of Mu light the monster can move along → a special interaction (to be defined). (The earlier "cancels Mu light" idea was dropped.)
- **Periphery scanner** (fan-made object `periphery-scanner` in `lore/data/objects.yaml`): unlimited (no charges); balances Mu light against baseline light, which are nearly antagonistic, and measures the drift of that balance near a periphery. Needs very high precision, one of Maroon's last experiments, left behind because of its quirks: a meter shows the reading from weak to strong periphery energy; a strong reading makes it let out a short burst of Mu light, a reverse flashbang (everything around goes pitch black for a moment). It can be turned off. No passive scanning: a button starts a reading, and each reading first needs a calibration that takes a while. Whether it goes off at the PCR surge is left to the GM. Lies in one of the test chambers in the labs.
- The thing in the dark: from the other side of the PCR, let loose by the surge, can only move in Mu light, never really seen. Glimpse scene: something comes out for a second, a cry, gone — a ripple where it banged against the wall of Mu light and couldn't get through.
- Maroon backstory: Mu research slowed and was partly scrapped (invisibility is of little use to people in exile in the Superstructure); staff moved off low-priority projects; Maroon abandoned with the scrapping; the PCR couldn't be looted because of Mu exposure.
